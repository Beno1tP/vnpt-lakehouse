The scheduler therefore admits pods up to 10.7 GiB of requests while the real cap is 8 GiB → whole-node OOM instead of `Pending`. CPU: `CpuQuota=0`, so all 8 CPUs are usable (not a problem: RAM is the bottleneck) | Recreate the (still empty) cluster with `--extra-config=kubelet.system-reserved=memory=3686Mi` → observed Allocatable **7442652Ki (7268 Mi)** = 11217116Ki − 3686 Mi (minikube sets `evictionHard` to `0%`, so no 100 Mi eviction margin is subtracted, unlike stock kubelet); node `kubepods.slice/memory.max` = 7621275648 bytes = the same 7268 Mi → pods are capped, ~0.9 GiB of the 8 GiB stays for kubelet/containerd | Allocatable = Capacity − kube-reserved − system-reserved − eviction-threshold; with `enforceNodeAllocatable=[pods]` (default) the kubelet sets the pods cgroup limit to Allocatable.
